# シンフリーサーバーへの公開手順

方針の背景は `docs/decisions.md` の D-9 / D-12 を参照。

所要時間の目安は 1〜2 時間。**ステップ 8 のパーマリンク保存を飛ばすと制作実績が全部 404 になる。**

---

## ステップ 1. アカウントを作る

https://www.xfree.ne.jp/ から申し込む。

- **1 人 1 件まで**（公式マニュアルに明記）
- シンクラウドの会員登録 → 無料レンタルサーバーの申し込み、の 2 段階
- 完了通知メールにサーバー ID とログイン情報が届く。**このメールは保存しておく**

---

## ステップ 2. ドメインを決める

2 通りある。

| | 費用 | URL の見え方 |
|---|---|---|
| **サブドメイン**（推奨・最初はこれで十分） | 0 円 | `https://好きな名前.あなたのサーバーID.xfree.jp` のような形 |
| 独自ドメイン | 年 1,000 円前後 | `https://example.com` |

サーバーパネルの「**サブドメイン設定**」から追加する。

決めた URL を控える。**ステップ 5 で使う。**

---

## ステップ 3. WordPress を入れる

サーバーパネルの「**簡単インストール**」→「WordPress 日本語版」。

- インストール先は**ステップ 2 で決めたドメイン**
- **管理者のユーザー名を `admin` にしない**（ローカルは `admin/admin` だが、公開サーバーでは即座に狙われる）
- パスワードは推測されないものにする

この時点で初期状態の WordPress が表示されれば OK。

---

## ステップ 4. ACF を先に入れる

管理画面 → プラグイン → 新規追加 → 「**Advanced Custom Fields**」を検索してインストール・有効化。

**順番が重要。** このあと入れる DB ダンプは ACF が有効な状態で保存されているため、
プラグインのファイルが無いまま DB を入れ替えると管理画面がエラーになる。

---

## ステップ 5. 書き出す（ローカルで実行）

```bash
cd /Users/admin/prc-project/portfolio/portfolio_wordpress
./bin/export.sh https://ステップ2で決めたURL
```

`bin/dist/` に以下が出る。

```
database.sql      URL を置換済みの DB ダンプ
wp-content/       テーマ・自作プラグイン・アップロード画像
README.txt        この手順の要約
```

URL の置換は `wp search-replace` で行っている。`sed` や SQL の `REPLACE` を使うと
シリアライズされた値の長さが壊れるため（詳細は README の「共用レンタルサーバーへの移設」）。

---

## ステップ 6. ファイルを上げる（FTP）

サーバーパネルの「FTP アカウント設定」で接続情報を確認し、FTP ソフト（FileZilla / Cyberduck など）で接続。

`bin/dist/wp-content/` の中身を、サーバー側の `wp-content/` へアップロードする。

```
themes/pacchi-portfolio/     → wp-content/themes/pacchi-portfolio/
plugins/portfolio-core/        → wp-content/plugins/portfolio-core/
uploads/                       → wp-content/uploads/
```

**既存の `themes/` や `plugins/` を消さない。** 中に追加する形。

---

## ステップ 7. DB を入れ替える（phpMyAdmin）

サーバーパネルの「phpMyAdmin」を開く。

1. WordPress が使っているデータベースを選ぶ
2. 既存のテーブルを**すべて選択して削除**
   （インポートは上書きではないため、消さないと重複してエラーになる）
3. 「インポート」タブ → `bin/dist/database.sql` を選択 → 実行

**この時点でサイトを開くと、ローカルと同じ内容が表示されるはず。**
管理者のログイン情報も**ローカルと同じ `admin` / `admin` に戻っている**ので、
ステップ 9 で必ず変更する。

---

## ステップ 8. パーマリンクを保存する（最重要）

管理画面 → **設定 → パーマリンク** → 何も変更せず「**変更を保存**」をクリック。

カスタム投稿タイプ `/works/` のリライトルールが再生成される。
**これを飛ばすと制作実績のページが全部 404 になる。**
「CPT を作ったのに個別ページが 404」は WordPress 案件で最も多いトラブルで、
原因の大半がこれ。

---

## ステップ 9. 管理者アカウントを安全にする

DB を入れ替えた結果、ローカルの `admin` / `admin` が復活している。

1. ユーザー → 新規追加で、**推測されないユーザー名**の管理者を作る
2. そのアカウントでログインし直す
3. 元の `admin` ユーザーを削除する（投稿の帰属は新しいユーザーへ移す）

ユーザー名を変えるのは、総当たり攻撃の入口を 1 つ減らすため。
本テーマは `inc/security.php` でユーザー列挙（REST API / 著者アーカイブ）を塞いでいるが、
`admin` は最初に試される名前なので使わない。

---

## ステップ 10. 常時 SSL にする

1. サーバーパネル →「**無料独自SSL設定**」で対象ドメインに SSL を追加
2. サーバーパネル →「ドメイン設定」→ 対象ドメインの詳細 →
   「HTTPS転送設定」の「**HTTPSに転送する**」にチェック → 設定する

`http://` でアクセスして `https://` に転送されれば完了。

**エクスポート時に `https://` で指定していれば DB 側は対応済み。**

---

## ステップ 11. 動作確認

以下がすべて表示されるか。

```
https://あなたのURL/                トップ
https://あなたのURL/works/           制作実績の一覧
https://あなたのURL/works/soranowa-koumuten/   実績の詳細
https://あなたのURL/tech/php/        技術タクソノミー
https://あなたのURL/存在しないURL     404 ページ
```

`/works/` が 404 なら**ステップ 8 をやり直す。**

---

## ステップ 12. お問い合わせフォームを試す

トップの「お問い合わせ」から実際に送信し、**メールが届くか確認する。**

シンフリーサーバーはメール機能が有料プラン対象と公式に明記されているため、
PHP からの送信が通らない可能性がある。

### 届かなかった場合

**外観 → カスタマイズ → サイト設定 →「お問い合わせフォームを表示する」をオフ**にする。

フォームが消え、メールアドレスの案内だけが残る。
「送信できたように見えて届かない」状態が一番まずいので、届かないなら出さない。

（外部 SMTP に切り替える方法もある。`mu-plugins/local-smtp.php` と同じ
`phpmailer_init` フックで Gmail や Brevo に向ける。必要になったら対応する）

---

## 公開後にやること

- **GitHub リポジトリの説明欄に公開 URL を追加**
- ポートフォリオの制作実績「WordPress ポートフォリオサイト」に
  サイト URL を設定し、ステータスを `released`（公開中）へ変更
  （`bin/seed/works.json` を編集して `seed-works.php` を流し直す）
- 工務店サイトも同様に公開する場合は別サーバーが必要
  （シンフリーサーバーは 1 人 1 件のため、サブドメインで運用するか
  ロリポップ等を検討する）

---

## つまずきやすい箇所

| 症状 | 原因 |
|---|---|
| `/works/` が 404 | ステップ 8 を飛ばしている |
| 管理画面が真っ白／エラー | ACF を入れる前に DB を入れ替えた（ステップ 4 の順番） |
| 画像が表示されない | `uploads/` のアップロード漏れ、または DB とファイルの不一致 |
| 一部の設定が消えた | `sed` や SQL の `REPLACE` で URL を置換した（`export.sh` を使えば起きない） |
| フォームが届かない | サーバーのメール制限。ステップ 12 |
