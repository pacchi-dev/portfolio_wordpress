# 決定事項と理由

「なぜその選択をしたか」を残す。実装中に方針がぶれたとき、また README を書くときの根拠になる。

## 決定済み

### D-1. 新規リポジトリとして作る（Next.js 版とは分ける）

Next.js 版リポジトリ `pacchi-dev/portfolio` はそのまま残し、
WordPress 版は別リポジトリにする。

**理由**: 応募先に「Next.js も WordPress も作れる」と 2 つの実績として並べて提示できる。
同一リポジトリで `main` を WordPress に置き換えると、Next.js 版がブランチを
掘らないと見つからない状態になり、実績として弱くなる。

**採らなかった案**: 同一リポジトリでブランチ分け。
Vercel のデプロイ対象ブランチ変更が必要になる点も難点だった。

**保全措置**: Next.js 版リポジトリに以下を作成済み。
- ブランチ `nextjs-version`
- タグ `v1.0-nextjs`（WordPress 版着手前の完成状態）

---

### D-2. クラシックテーマをフルスクラッチで作る

ブロックテーマ（FSE）でも既製テーマの子テーマでもなく、クラシックテーマを自作する。

**理由**: 国内の WordPress 案件（軽微修正・既存テーマ改修・functions.php 修正）は
圧倒的にクラシックテーマが対象。テンプレート階層・The Loop・hooks の理解を
示すのに最適。

**採らなかった案**:
- ブロックテーマ / FSE → 案件需要が現時点では小さい
- 既製テーマの子テーマ改修 → 「テーマ修正案件」の練習にはなるが、制作力の証明としては弱い

---

### D-3. テーマとプラグインで責務を分離する

CPT・タクソノミー・GitHub API・お問い合わせ処理はテーマに入れず、
自作プラグイン `portfolio-core` に置く。

**理由**: 「テーマを変えてもコンテンツと機能が生き残る」という WordPress の原則。
テーマに CPT を書くのはアンチパターンとして知られており、
分離していること自体が理解度の証明になる。

---

### D-4. プラグインは最小限（ACF + Query Monitor のみ）

ページビルダー・SEO プラグイン・既製テーマは使わない。

**理由**: 「不要なプラグイン依存を避ける」という品質要件。
プラグインを積むほど「WordPress を理解して作った」証明にならなくなる。

---

### D-5. お問い合わせフォームは自作する（CF7 を使わない）

**理由**: nonce / sanitization / `wp_mail` を自分で書く経験を優先する。
これらは WordPress のセキュリティ実装の中核で、案件でも問われる。

**トレードオフ**: 実案件では CF7 が標準的に使われるため、CF7 の実務経験は積めない。
README に「実案件では CF7 が標準的だが、今回は学習目的で自作した」と
使い分けの判断ができることを明記して補う。

---

### D-6. ACF は無料版を前提に設計する

Repeater・Options Page（Pro 機能）を使わない設計にする。

- Options Page の代わり → フロントページ固定ページに ACF フィールドを付ける
- Repeater の代わり → 改行区切りの textarea

**理由**: 無料版での回避策は実案件でも頻出のパターンであり、
この制約下での設計自体がスキルとして示せる。

---

### D-7. 使用技術はタクソノミーで管理する（ACF フィールドにしない）

`technology` カスタムタクソノミーを work / experience 共通で使う。

**理由**: 技術名を ACF のテキストフィールドで持つと表記ゆれが発生し、
「この技術を使った実績一覧」も作れない。タクソノミーなら
アーカイブページが自動生成され、Skills セクションとも単一ソースで連動できる。

---

### D-8. 画像は標準のアイキャッチを使う（ACF の画像フィールドにしない）

**理由**: アイキャッチは `has_post_thumbnail()` / `the_post_thumbnail()` など
WordPress 標準の関数群・REST API・OGP 生成と連携する。
ACF の画像フィールドにすると、これらの恩恵を自分で再実装することになる。
**「標準機能で足りるものは標準機能を使う」という判断ができることの証明。**

---

### D-9. 公開は受注後。それまではローカルで完結させる（U-1・U-2 の決着）

CrowdWorks / Lancers の応募では「実績・ポートフォリオ URL」の提示を求められるため、
公開先を早く用意したくなるが、以下の理由で**受注後まで公開しない**と決めた。

| 検討した案 | 却下・保留の理由 |
|---|---|
| Next.js 版を Vercel へ公開（U-1） | **却下**。WordPress 案件に応募するのに WordPress で作っていないものを見せても説得力が薄い。プロンプト 4 で作る工務店サイトも WordPress なので Vercel には載らない |
| レンタルサーバーの 10 日間無料お試しで応募時だけ公開 | **却下**。応募〜契約は 10 日で終わらず、期間終了で URL が消える。加えて Xserver はお試し中「サーバープログラム(CGI/PHP等)によるメール送受信」が制限され、**問い合わせフォームが動かない** |
| ローカルで制作し、スクリーンショット + ソースで見せる | **採用**。費用 0 円。受注できたら有料契約する |

本番ホスティング（U-2）は **ロリポップ（共用サーバー）** を第一候補とする。

- CrowdWorks の WordPress 案件 143 件を調べたところ、**AWS は 0 件**。
  サーバー名が出る 17 件では Xserver 7 / ロリポップ 2 / さくら 2 / お名前.com 2 だった
- ただし **88% の案件はサーバーを指定していない**ため、どれを選んでも応募で不利にはならない
- 管理画面・FTP・phpMyAdmin・独自 SSL といった共用サーバーの作法は各社共通で、
  「サーバー移行・復旧」案件（150 件中 11 件）で効くのはこの共通スキル
- ロリポップ ハイスピード（月 660 円〜）は独自ドメイン 2 つ無料。
  1 本目をポートフォリオ、そのサブドメイン（`demo.〜`）に工務店サイトを置く

将来の移設に備え、サーバー固有機能に依存せず、パスをハードコードしない。

### D-11. アーキテクチャ図は SVG で描画する

ACF のテキストエリアに書いた ASCII アートを `<pre>` でそのまま出していたが、
全角と半角が混在すると桁が揃わず、実際に図が崩れていた。

1 行の簡易記法をパースしてインライン SVG を生成する方式に変更した。

```
Client -> Load Balancer -> *Go API (Echo)* -> PostgreSQL, Redis
```

- `->` で列（処理の流れ）を区切り、`,` で同じ列に並べ、`*` で囲むと強調
- 実装は `pp_render_architecture()` / `pp_parse_architecture()`（テーマの `inc/template-tags.php`）

**なぜ画像ファイルではなく SVG か**

- リクエストが増えない（`the_post_thumbnail()` と違いアセットを追加しない）
- `currentColor` とカスタムプロパティでテーマの配色に追従する
- 拡大しても劣化せず、`max-width: 100%` でモバイルにも収まる

記法として解釈できない入力（改行を含む従来の ASCII 図など）は、
これまでどおり `<pre class="arch-diagram">` にフォールバックする。
既存データを壊さないための保険で、表示方法を変える改修では定石。

### D-12. 公開先はシンフリーサーバー（無料）から始める

D-9 では「受注後にロリポップ（月 660 円〜）」としていたが、
無料で公開できる選択肢を調べ直した結果、方針を前倒しする。

**調査で分かったこと**

無料レンタルサーバーは終了が相次いでいる。

| サービス | 状況 |
|---|---|
| XFREE（エックスサーバーの無料版） | 2025/07/31 終了 |
| StarServer Free（スタードメイン） | 2025/03/31 終了 |

ネット上の「無料サーバーおすすめ」記事の多くが、終了済みのサービスを
紹介したままだった。現役で条件を満たすのは **シンフリーサーバー**（XFREE の後継、
エックスサーバー系）。

| 項目 | 内容 |
|---|---|
| 料金 / 広告 | 完全無料・広告表示なし |
| 容量 | 10GB（NVMe SSD） |
| WordPress / PHP / MySQL | 利用可 / PHP 8・7 / MySQL |
| 独自SSL | 無料・無制限 |
| 独自ドメイン・サブドメイン | 対応 |
| 転送量 | 900GB/日 |
| Cron / .htaccess / mod_rewrite | 利用可 |
| **メール機能** | **有料プラン（シンフリーサーバープラス）対象** |

**なぜロリポップより先にこれを試すか**

- 費用が 0 円。受注前の段階で支出を発生させない
- エックスサーバー系のため管理画面の操作感が Xserver に近い。
  CrowdWorks 調査でサーバー名が出た 17 件のうち Xserver が 7 件で最多だった
- 合わなければロリポップへ移す。その移設作業自体が
  サーバー移行案件（150 件中 11 件）の練習になる

**リスクと受け止め方**

無料サービスは終了しうる（同社の XFREE が実際に終了している）。
ただし終了には事前告知があり、10 日間無料お試しのような突然の停止とは異なる。
位置づけは「受注までのつなぎ」とする。

**メール送信について**

公式マニュアルに「メール（シンフリーサーバープラス対象）」と明記されており、
メール機能は有料プラン限定。無料プランで PHP からの送信が可能かは
公式に記載がなく、実機で確認するまで断定できない。

対応の順序は以下とする。先に諦めるとフォームが動いたかどうか分からないまま、
nonce・サニタイズ・ハニーポットを自作した showcase を 1 つ失う。

1. 実機で wp_mail() の送信を試す
2. 失敗したら外部 SMTP に切り替える
   （mu-plugin に phpmailer_init のフックが既にあり、ローカルでは Mailpit へ向けている）
3. それも不可なら、カスタマイザーの「お問い合わせフォームを表示する」を
   オフにし、メールアドレスの案内のみにする

3 のためにフォームを条件分岐で囲んだ。コードを削除しないのは、
環境ごとに送信可否が変わるため。移設先で送信できるなら戻せる。
